## 구현 완료 보고 — M3

### 구현 의도

M2까지의 정착지에는 "공간"이 없었다. 사람은 목표 쪽으로 한 칸씩 부호만 보고 걸었고(벽이 있어도 지나갔고), 지을 수 있는 것은 움막과 작업장뿐이었으며, 방이라는 개념이 없었다. M3는 ROADMAP의 한 줄 — **"언덕을 파서 만든 방이 창고가 되고, 사람들이 그리로 나른다"** — 을 위해 세 가지를 차례로 쌓았다: **경로 찾기**(ADR 0021: 비용 지도, 영역, A*와 메모), **벽·문·바닥·침상·언덕 파기**(ADR 0022: 물건으로 짓는 1×1 공간 부지, 철거, 파기), **방과 역할**(ADR 0023: 방 인식, 침실·창고·작업장·홀, 역할이 잠·운반·제작을 바꿈). 그리고 Part 0에서 M2의 후속 세 가지(기술 동점 처리, 품질 단어, 경제 장기 고정 시험)를 끝냈다. 기준 커밋은 `v8/wip` = `f0ba4347`, `v8/main` = `4874c9dc`, 작업 시작 2026-10-22 17:05 KST.

### 구현 방법 (A*와 메모·증분 갱신, 방 탐지와 id 안정성, 역할 판정과 효과 수치, 재료 흐름, 결정 틱 접점 줄 수)

- **증분 갱신**: 통행 판정은 `runtime::nav::tile_cost` 하나뿐이고, 타일을 바꾸는 코드(벽 완공·철거, 문, 파기, 부지 놓기·취소, 세계 생성의 길 열기)가 그 자리에서 `nav::refresh`를 부른다. 비용이 바뀌면 `nav.version`이 오르고, 영역과 메모는 다음에 쓸 때 그 버전으로 다시 만든다. 다시 만든 지도와 증분 지도가 같음을 시험한다(`colony_nav.rs`).
- **메모**: `(출발, 도착)` → 경로, 한 버전 안에서만 유효, 4,096개, 넣은 순서로 밀어냄. 메모 적중은 같은 버전의 새 탐색과 같은 답이므로 행동을 바꾸지 않고 저장하지 않는다. 걷는 사람의 경로는 저장하고, 버전이 바뀌면 남은 걸음을 다시 확인해 막혔을 때만 새로 찾는다.
- **영역**: 목표가 다른 영역이면 탐색 없이 "없음". 일감 배정은 일꾼 영역에서 닿는 대상만 보고, 빈 탐색 기억도 영역별로 둔다.
- **방 id**: 새 방은 옛 방 중 자기 칸의 50 % 이상을 가진 방(겹침이 가장 큰 방, 같으면 낮은 id)의 id를 이어받는다. 역할 고정은 id를 따라간다.
- **역할과 효과 수치**: 침실 피로 800 ‰(회복 20 % 빠름), 작업장 방 제작 900 ‰, 창고 우선은 가장 가까운 칸보다 16칸 이상 멀지 않을 때, 닿지 않는 대상 냉각 1일, 방 2–120칸(목표 값 그대로).
- **재료 흐름**: 벽·문·침상의 재료는 완공 때 소모, 철거하면 절반이 그 재료로 다시 생기고, 파기는 돌 3개를 만든다. 종류별 장부는 모든 시험·장기 시험·평가 실행에서 매 틱 정확했다(위반 틱 0).
- **결정 틱 접점**: `runtime/decision/system.rs`는 M3에서 **한 줄도 바뀌지 않았다**(`git diff --numstat f0ba4347 3d73712d` 0줄; 상한 +20). 결정 목표의 도달 처리는 이동 시스템에서, 욕구 직전 일감 금지는 일감 배정에서 한다.

### 성능 계획과 실제 (nav_bench 전후, 적용한 조치와 효과, 벤치 장부)

- 계획(D2, 경로 코드 전에 등록): N = 1,000, 장기 시험 대본에서 이동 + 경로 ≤ 0.6 ms/틱; 요청 100틱당 ≤ 200, 탐색당 펼친 노드 ≤ 2,000, 메모 적중 ≥ 60 %.
- 실제(`worldsim_perf nav-bench`): 이동 + 경로 **103.7 µs/틱**(`71c896b6`), **112.0 µs/틱**(`3d73712d`), **92.5 µs/틱**(`23be0178`, 최종 시뮬레이션) — 예산의 1/5 정도. 펼친 노드 53–69(예상보다 훨씬 적음). 그러나 **요청은 100틱당 4,600–5,500회**(예상 200)이고 메모 적중은 49–59 %, 경로 없음 약 54,000회 — 예상이 틀렸다. 예산 안이라 계획의 대책(청크별 경로 재사용, 흐름장 캐시 6.4, 재계획 상한)은 만들지 않았다. 측정은 공유 맥의 부하 18–26에서 했다.
- 벤치 장부(`docs/perf/PERF_LEDGER.md` "base M2"·"M3" 블록): 기준 `f0ba4347`과 `23be0178`을 한 세션에서 번갈아 3바퀴 쟀다. 45분을 기다려도 부하가 내려가지 않아(크롬·스포트라이트, 1분 부하 19–25) **경합 세션**으로 적었다. 같은 세션의 기준 대비 틱 평균: N = 200 ×0.85, N = 1,000 ×1.049, N = 2,000 ×1.049, 대본 장면 ×0.953, 64² 장면 **×1.240**(+46 µs). 늘어난 몫은 경로 찾기다: N = 1,000에서 이동 23 → 96 µs, 일감 배정 64 → 123 µs(영역 검사).
