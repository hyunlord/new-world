## 1. 무엇을 만드는가

**한 줄:** 석기시대의 작은 무리가 마을이 되는 과정을, 사람 하나하나의 몸·마음·관계·기술이 서로 맞물려 만들어 내는 드워프 포트리스·림월드식 정착지 시뮬레이션. 모든 사건에는 따라갈 수 있는 원인이 있다.

**v1.0:** 10명으로 시작해 몇 년 안에 약 100명이 되고, 신석기 시대로 넘어간다. 사람마다 성격·기억·관계가 있고, 그 일생과 마을의 역사를 읽을 수 있다. 1만 명, 청동기 이후, LLM 해설은 v1.0 밖이다.

**만들지 않는 것 (경계):**
- 신 게임이 아니다. 지형을 그리거나 사람을 직접 조종하지 않는다(ADR 0001, 0010). 소집만 예외(ADR 0007).
- 실패 없는 장난감이 아니다. 굶주림·추위·짐승·기술 소실로 마을이 망할 수 있고, 망한 이유를 따라갈 수 있어야 한다.
- 시스템 개수로 깊이를 재지 않는다. V7은 시스템 59개에 실제 작동 30 %, 30명에서 60 FPS 미달이었다.

## 3. 원칙

1. **맞물림으로 깊어진다.** 새 시스템은 기존 시스템 둘 이상에서 입력을 받고 둘 이상에 출력해야 들어온다.
2. **보이지 않으면 없다.** 모든 내부 상태 변화는 정보창·연대기·"왜?" 중 하나에 나타난다. 오너가 읽는 연대기는 사건을 고르고, 두뇌 선택 같은 세부 기록은 "왜?" 쪽에 둔다.
3. **효과마다 원인 기록.** 원인 사슬이 실제로 이어지는지 이야기 수확량(깊이 ≥ 3 사슬 수)으로 매 패스 잰다.
4. **막대는 산수부터.** 기댓값을 지금 규칙으로 계산해 설계 문서에 적고 고정한 뒤 구현한다. 사건이 일어나지 않은 세계는 분모에서 뺀다(M-UX2 한파 교훈).
5. **콘텐츠는 데이터, 행동은 코드**(ADR 0033). 새 기둥은 두뇌에 사실 제공자 + 행동 + `mind.ron` 노드로 꽂는다(MIND_AUTHORING).
6. **결정론과 기준선.** 정수·permille·키 난수. 기준선(V7) 동일성은 매 커밋 바이트 단위로 지킨다.
7. **성능은 설계 단계에서.** 하루·계절 경계에서만 갱신, 틱마다 전체 훑기 금지, 상세 LOD는 M11.
8. **매 패스 오너 확인.** 오너가 플레이하지 않을 때는 캡처로 대신 확인하고 보고서에 붙인다.

## 7. 작업 방식

| 역할 | 누가 | 하는 일 |
|---|---|---|
| 오너 | Kwan Hyeon | 방향 결정, 플레이 또는 캡처 확인, 의뢰서 전달 |
| 기획자 | Claude | 저장소를 읽고 설계, 의뢰서, 보고서 검증(GitHub에서 SHA·숫자 직접 확인) |
| 실행자 | Codex(GPT Astra), 필요 시 Claude Code | 자기 작업 트리에서 구현·게이트·게시 |

규칙(겪고 나서 생긴 것 포함):
- **작업 트리는 패스마다 따로.** pass4·play2-dev는 건드리지 않는다. 한 작업 트리에 세션 하나.
- **성능을 재는 작업은 한 번에 하나.** 같은 맥에서 두 작업이 동시에 재면 둘 다 무효다(2026-10-26).
- **측정 조건:** 반복마다 1분 부하 < 8(성능 장부 규칙), 옛/새 바이너리를 같은 시간대에 번갈아 잰다.
- **빨간 게이트는 고치고 다시 돌린다.** 멈추는 건 코드 충돌, 고칠 수 없는 동일성 실패, 상한 시간뿐.
- **이슈 번호는 게시할 때 정한다.** 게시 전에는 패스 임시 번호(M6A-1 …)를 쓰고, 게시하면서 다음 빈 ISS 번호로 바꾼다(2026-10-28 ISS-333 충돌).
- **문서 충돌은 양쪽을 살린다.** 코드·데이터 충돌만 멈춤 사유다.
- **held-out 시드 대장:** 1200–1231 M-UX2, 1232–1263 M-CORE, 1264–1295 M-CORE P-3d, 1296–1327 M6a. 다음 패스는 1328부터 32개씩.
- **보정은 시드 0–7, 4회까지, 고정한 뒤 held-out.** 결과를 보고 고치지 않는다.

- (2026-10-31, 오너 결정 O-2) 첫 보정 회차에서 0/8인 막대는 명세 결함 의심으로 본다. 멈추고 원리를 보고하며, 동결·held-out 사용 전에 오너가 막대를 확정하거나 철회한다.

# Appendix A — 깊이 로드맵 (오너 승인 2026-10-26; `docs/v8/DEPTH_ROADMAP.md`로 커밋)

## v1.0 정의
10명으로 시작해 몇 년 안에 약 100명이 되고, 신석기 시대로 넘어간다. 사람마다 성격·기억·관계가 있고, 그 일생과 마을의 역사를 읽을 수 있다. 1만 명, 청동기 이후, LLM 해설은 v1.0 밖이다.

## 원칙
1. **맞물림으로 깊어진다.** 새 시스템은 기존 시스템 둘 이상에서 입력을 받고 둘 이상에 출력해야 들어온다. 시스템 수를 목표로 삼지 않는다(V7: 59개 시스템, 실제 작동 30 %).
2. **보이지 않으면 없다.** 모든 내부 상태 변화는 "왜?", 연대기, 사람 상세 중 하나에 나타난다.
3. **효과마다 원인 기록.** 모든 효과는 원인 레코드를 가리킨다.
4. **막대는 산수부터.** 기댓값 계산을 설계에 적고 나서 막대를 정한다.
5. **성능과 규모는 설계 단계에서.** 시스템마다 상세 LOD(가까운 사람은 전부 계산, 먼 사람은 요약)를 정한다.
6. **이야기 수확량을 잰다.** 세계 1년당 깊이 3 이상 원인 사슬 수, 서로 다른 사슬 종류 수, 기록이 3개 이상인 사람 수(M-CORE §7)를 매 패스 보고한다.
7. **매 패스 오너 플레이.** 설계 → 산수 → 구현 → 보류 시드 평가 → 오너 플레이.
8. **콘텐츠는 데이터, 행동은 코드**(ADR 0033). 새 기둥은 사실 제공자 + 행동 + `mind.ron` 노드로 꽂는다.
