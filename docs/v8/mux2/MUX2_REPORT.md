final-stall1과 final-stall2는 각각 두 배율에서 310초 캡처를 완료했다. 첫 10초 이후 50 ms 초과 0회, 분당 33 ms 초과 3회 이하라는 기준을 유지한다. 원시 캡처의 완료·계측 상태와 오류 목록은 정상이나, wrapper 영수증은 기준 실패에 따라 complete false / exit 1이다. 어느 기록도 지우거나 성공으로 바꾸지 않는다.

`reviews/final-stall1-analysis.md`에 따르면 ½×의 1초 지연은 시작 후 12.421–13.429초에 발생했다. 대부분이 pre-draw→post-draw 구간에 있으며 측정된 Rust나 지면 준비 시간으로 설명되지 않는다. 첫 배율의 큰 보고서를 두 번째 배율 실행 중 읽은 호스트 작업은 **오염 후보**지만 시간 기준이 달라 직접적인 원인으로 확정하지 못했다. 이를 제품의 1초 회귀로 단정하거나 채점에서 제외하지 않는다.

마지막 분의 초과 프레임 6개는 이 초기 이상치와 독립적으로 빈도 기준을 위반한다. 해당 프레임의 지면 처리는 약 13–14 ms, 그중 `GroundLayer._update_trees`는 약 10–11 ms였다. 다른 처리와 스케줄링 지연도 포함되므로 나무 갱신만으로 전체 지연을 설명하지 않는다. 후속 측정은 두 배율이 모두 끝날 때까지 보고서를 읽거나 출력하지 않는 격리 조건이 필요하다. 기존 FAIL은 보존한다.

조명 준비는 실제 shader receiver로 검증했지만 특정 드라이버의 shader compile이 유일한 원인이라고 단정하지 않는다. 오래된 `last_bake`나 누적 최악값을 현재 프레임으로 세지 않고 실제 추가된 bake event로 구간을 나눈다.


트리 변환 후보는 같은 이름의 GString 변환을 재사용하며 native 2검사와 실제 Godot 22검사에서 전체 사전 일치를 확인했다. 고유 변환 횟수의 정방향·역방향 실패 대조군과 최초 컴파일·서식 실패를 보존했다. final-stall2에서 실제 getter 시간의 개선이 입증되지 않아 채택을 거부하기로 했다. p14 게이트 종료 뒤 후보의 생산·probe·검사 연결 6경로를 p13과 정확히 같게 되돌렸다. 캡처 수정과 기존 oracle은 유지했다. 제거 뒤 검증은 별도로 기록한다. 앞선 owner-tags 제거 당시(p14 트리 후보 유지)의 Python 73검사(16.741초)와 기존 전체 oracle·실제 tree probe는 PASS였다. 이번 트리 제거 뒤에는 Python 전체 191검사(33.000초), fmt·workspace/all-targets clippy·debug bridge build와 docs/schema가 PASS다. 이 결과로 최신 소스의 전체 Rust 시험이나 전체 게이트를 대신하지 않는다. p15 전체 게이트는 40/41·exit 1이며, 빌드 뒤 새로 캡처하도록 순서를 고친 후 p16 전체 게이트는 41/41·status 0으로 완료했다.

ISS330 수정은 `frame_post_draw`를 주 계수로 쓰고 Engine 계수와 비교하며 창 상태를 기록한다. windowed/topmost 조건에서 FPS8과 FPS9의 두 렌더 계수가 일치했다. `force_draw`나 process-frame FPS로 대체하지 않았고 측정 시간과 기준도 유지했다. 캡처 과정의 수정은 FPS 성능 성공과 별개다.


`final-stall2-summary.json`과 `reviews/final-stall2-analysis.md`는 두 배율의 캡처·계측 완료, 오류 없음과 **1× PASS / ½× FAIL**을 확인한다. debug Metal/Forward+, vsync 1, 프레임 제한 없음 조건이며, 루트는 두 캡처 동안 보고서 읽기·빌드·다른 GPU 작업이 없었다고 기록했다. 어떤 프레임도 채점에서 제외하지 않았다.

½×의 50 ms 초과 5개에는 모두 실제 트리 조회와 청크 굽기가 없었다. 3개는 pre-draw→post-draw 구간이 지배적이며 GPU 실행·표시 대기·드라이버·OS 스케줄링 중 어느 하나로 원인을 확정하지 못했다. 138초 부근은 공간 조회와 여러 native 시스템이 함께 늘어난 넓은 처리 지연이다. 뒤따르는 샘플링 16.293 ms는 다음 프레임에 귀속되므로 중첩 시간을 합산하지 않는다. 외부 간섭이나 일반적인 GC 원인을 입증한 것도 아니다.

트리 조회는 각 배율에서 준비 이후 55프레임, 마지막 분에 24프레임이었다. ½× getter 중앙값은 6.732 ms, 트리 처리 중앙값은 11.574 ms였다. stall1의 늦은 실패 6틱과 맞춰 비교하면 getter가 약 5.776–6.054 ms에서 6.604–6.684 ms로 관측됐다. 전체 프레임의 마지막 분은 나아졌지만 이 구성요소는 개선되지 않았다. 두 계측 실행만으로 캐시의 인과적 성능 회귀를 증명할 수는 없다. 수천 회 대신 3회 변환했다는 사실만으로 채택하지 않으며, 개선 근거 부족을 이유로 후보를 거부한다. 기존 실패와 캡처는 모두 보존한다.


이전 `final-stall3-summary.json`과 독립 감사 `reviews/final-stall3-audit.md`는 p15의 두 310초 캡처를 모두 PASS로 확인했다. 감사는 원래 첫 10초 제외 규칙과 엄격한 33/50 ms 기준으로 모든 구간·분별 횟수를 다시 계산했다. 시작 구간 최대 3,828.224 / 4,329.481 ms는 원자료에 보존하며 원래 규칙에 의해서만 점수에서 제외했다. ½× 최대값의 여유는 **0.171 ms**뿐이다. 이는 한 번의 유효한 끊김 측정 성공이며 캐시 제거가 원인이라는 증명은 아니다. 앞선 stall1/2와 p14 전체 게이트 실패는 그대로 유지한다.
