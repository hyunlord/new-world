## 구현 완료 보고 — M2

### 구현 의도

M1과 M1.5의 정착지에는 물건이 통나무 하나뿐이었고, 작업장도, "무엇을 만들어 달라"는 주문도, "누가 무슨 일을 하라"는 지시도, 숙련도도 없었다. M2는 이후 모든 마일스톤이 쓰는 경제의 고리를 만든다: **자원 노드 → 채집 일감 → 비축 구역의 물건 → 작업장의 제작 주문 → 일을 바꾸는 도구 → 속도와 품질을 바꾸는 기술**. 그리고 3,490줄 결정 틱(ADR 0016 C5)을 해체하는 첫걸음으로 **장작을 결정 틱에서 일감으로** 옮겼다. 그 전에 Part 0에서 이번 주 아트 트랙의 결정을 메인 라인의 문서로 옮겼다. 기준 커밋은 `v8/main` = `v8/wip` = `e5594e3f`, 작업 시작 2026-10-22 08:42 KST.

### 구현 방법 (장부 변환 기록, 주문 스케줄링 키, 속도·품질 표의 근거, 재료 정수화, 장작 변환, 결정 틱 제거 범위와 줄 수)

- **장부와 변환:** 종류마다 `생성 = 땅 + 손 + 도구 + 현장 + 선반 + 소모`를 매 틱 확인한다. 제작은 변환이다: 시작할 때 재료를 `consumed`·`craft_inputs`로, 끝날 때 산출물을 `created`·`crafted`로 기록한다. 재료는 **시작할 때 소모**한다(ADR 0019): 도중에 취소된 제작은 재료를 잃고(`crafts_lost`), 이를 드물게 하려고 일하는 중인 제작자는 위급한 배고픔·목마름에만 일을 놓는다(D13; 평가 32세계에서 잃은 제작 0).
- **주문 스케줄링:** 작업장은 id 순, 주문은 목록 순; 첫 실행 가능 주문이 활성(`BillSystem`, 매시와 명령 직후). 배정은 우선순위 단계(1→4)마다 사람을 `AgentId` 순으로, 한 단계 안에서는 `WorkType` 순(제작 > 건축 > 채석 > 벌목 > 장작 > 운반), 그다음 가까운 순(`(거리, y, x)`). 품질 보너스는 `(시드, STREAM_QUALITY, 사람, 틱, 주문)` 키 추첨 하나.
- **표의 근거(ADR 0020, D10):** `XP_TABLE[L] = 15·L² + 15·L`(5레벨 450, 20레벨 6,300 작업 틱); `SPEED_PERMILLE` 1400(0) → 1000(5) → 700(20); 품질 `30 + 3·레벨 + 보너스(−10…+15, 삼각 가중치 27 − |2v − 5|, 평균 +2.5) + 재료(날만: (경도 − 50)/5, 부싯돌 +4) + 기질(끈기 ≥ 600 ‰ +2)`; `AXE_PERMILLE = 600 − 15·구간`. 0레벨 날 평균 약 36, 10레벨 약 66.
- **재료 정수화(D4):** 경도 = 모스 × 100, 밀도 = kg/m³ × 1000 / 25,000, 가공성·가연성 × 1000; `round()` 한 번, 초월 함수 없음.
- **장작 변환(D15):** 장작 물건 1개 = 정착지 장작 1단위. `HearthFeedSystem`이 매시(불 피우기 147 바로 전) 그날 밤 땔 만큼만 비축 구역과 화덕 더미(2칸 안)의 장작을 가까운 순으로 가져가 `burned`로 기록한다; 나머지는 물건으로 보인다. 장작이 모자라면 목공대 주문을 못 돌릴 때 마른 나무를 줍는다(`Gather`); 모자람은 화덕이 실제로 쓸 수 있는 장작만 센다(D19).
- **결정 틱 제거 범위:** 정착지에서 결정 틱의 장작 분기 전부 — 장작 계획·긴급 창·몫 나누기·`GatherWood` 분기·여가의 장작 출구·빈 자리 재지정 — 가 꺼진다(`decision_firewood`가 `None`). 짐을 든 사람의 음식 확인은 규칙을 직접 읽어 그대로 둔다(D21 m3). `decision/system.rs` 변경 +3 −2줄(순 +1). 정착지 실행에서 `GatherWood` 상태는 64개 실행 전체에서 0 에이전트-틱.
