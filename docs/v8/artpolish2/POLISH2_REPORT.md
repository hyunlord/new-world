수정은 이전 첫 시도 원본을 다섯 번째 참고 이미지로 붙여 수행하며, 이미지 도구가 얼굴·구도를 유지하면서 원본 의복 또는 수염·여백을 수정하도록 요청한다. 원본 해시와 불변 처리 기록을 현재 룩·변형·요청에 결속한다. 다른 변형의 유효한 이전 기록을 끼워 넣을 수 있었던 검토 실패는 수정했고, 최초 실패와 회귀 검증을 `PORTRAIT_PROTOCOL_REVIEW.md`에 보존했다. 코드로 초상 픽셀을 부분 수정하거나 세 번째 생성을 하지 않는다.

최초 수정 시험 `child_F_hide_wrap_bun/v1`은 의복 높이가 약 5–8px 개선됐고 머리 여백 21px, 머리 형태와 얼굴 유지, 새 목둘레·장식 없음이 관측됐다. 그러나 원본과의 높이·각도 대응은 여전히 FAIL이다. 개선본을 선택하되 실패를 그대로 유지한다.

고정된 47개 수정 생성은 모두 완료했다. 최종 호출은 **초상 281회(첫 시도 204 + 두 번째 시도 77) + 텍스처 39회 = 320/320회**, 도구 오류 0건이다. 초상별 최대 두 시도, 텍스처별 최대 세 시도를 지켰다. 불변 `call_inventory_r1.json`이 전체 호출을 기록하며 추가 생성은 없다.

성인 수정 9개는 모두 구조·머리·의복 대응을 통과해 두 번째 시도를 선택했다. 어린이 수정 38개의 실제 두 번째 시도는 구조 37/38, 머리 38/38, 의복 33/38이었다. 그중 36개를 선택하고 두 개는 첫 시도를 유지했다. `child_F_loincloth_bun/v4`는 의복 개선과 함께 머리 여백이 2px에서 약 1px로 줄었고, `child_M_hide_wrap_bun/v1`은 원본에 없는 소매 같은 어깨 의복이 생겼기 때문이다. 두 실패 시도와 소모된 호출도 기록에서 지우지 않았다.

구조 실패 세 개는 소진된 성인 남성 fur/bun v1과 어린이 남성 fur/bun v3·v5의 머리 여백이다. 남성 성인 fur/bun v1·v6의 수염 불일치도 남는다. 최종 초상은 첫 시도 129개·두 번째 시도 75개이며, 이번 수정으로 실제 바뀐 초상은 45개다. `art/portrait/polish2/GENERATION_MANIFEST.json`은 선택된 시도와 모든 실제 시도의 요청·참조·원본·관측·처리 기록 해시를 구분하며, `FINAL_PORTRAIT_POOL_CHECK.json`은 204개 초상의 128px 크기·실제 파일 해시·변하지 않은 틴트 참조 및 최초 후보군과의 차이를 독립 확인한다. 최종 후보군 동결 후에는 초상과 인덱스를 쓰지 않고 두 번째 맹검을 수행한다.

## 보드

최종 생성·검증 진행 중. `walls_material_strip.png`, `faces_owner.png`, `crowd_faces.png`와 필요한 무손실 2× 보충판을 제공한다. 파일당 1.5MB 상한을 지키기 위해 벽 전체 2× 장면은 a/b/c 보충판으로 나누며, 1× 장면이나 원래 픽셀을 축소·손실 압축하지 않는다.

ENV1 장면은 실제 캡처의 인물 ID를 사용한다. 캡처에는 수치 나이가 없고 life_stage만 있다. 합성기는 어린이/성인/노인용 대표 나이 10/30/50을 정의하지만, 이번 캡처 10명은 모두 성인이어서 실제로 적용한 값은 30뿐이다. 이는 실제 인물 나이를 관측했다는 뜻이 아니다. 소스 인물 10명 중 ID 0·1·2·3·4·5·8·9만 뷰포트에 보이고 ID 6·7은 화면 밖이다. 회색 v4를 배정받은 ID 7도 보이지 않으므로, 이 판으로 어린이·노인 표시나 60명 군중 검증을 주장하지 않는다.

최종 `crowd_faces.png`는 1600×900·1,100,451바이트이며, 동일 조건 무틴트 비교에서 장면 2,870픽셀이 바뀌었고 모두 보이는 인물 영역 안에 있다. 10개 선택 프레임 모두 알파가 같고 마스크 밖 RGB 변화는 0이다. 실제 1× 관찰에서 피부·머리 색 차이를 확인했다. 군중판은 동일한 ENV1 장면의 인물 비교를 위해 기존 벽 표현을 유지하며, 윗면 채택은 별도의 a/b/c 재료판에서 판단한다. 근거는 `FINAL_CROWD_BOARD_EVIDENCE.json`이다.

## M-ART2에 넘길 것

Godot 연동 입력은 표준 JSON과 PNG이며, 실제 게임 로더·셰이더 연결은 이 패스에 포함하지 않는다. 재료 세 JSON은 `schema_version: 1`, 틴트 기록은 `schema_version: 2`다. 로더는 버전을 검사하고 아래 키로 색인한 뒤, 기록된 저장소 상대 경로를 프로젝트 자산 경로로 매핑해야 한다.

| 입력 | 읽을 필드와 의미 |
|---|---|
| `construction_styles.json` | `styles`의 `id`, `kind`, `textures`, `top`, `face`, `ends`, `corner`; `default_styles` |
| `material_looks.json` | `materials`의 `id`, `sim_id`(u32), `category`, 선택적 `tint`·`texture_override` |
| `category_defaults.json` | `categories`의 `category`, `default_style`, `kind_defaults`, `tint` |
| `FACE_VARIANTS.json` | 룩별 `variants`, 나이·피부·머리·수염 축, `fallbacks`; 고정 샘플도 함께 보존 |
| `variant_transforms.json` | `(look, variant)`별 `skin_delta_lab`, `hair_delta_lab`, 원본 Lab 평균·목표 RGB, `frame_count: 10`, `mask_pattern`, `baked_pattern` |
| `variant_masks/MANIFEST.json` | 원본·마스크·베이크 해시, 의미 검토 연결, 프레임별 커버리지와 미통과 상태 |
| `portrait/polish2/GENERATION_MANIFEST.json` | 룩·변형별 선택 초상과 틴트 참조의 저장소 상대 경로·해시, 선택 시도와 시도별 외부 원본·관측·불변 처리 기록 |

색 공간은 CIELAB D65다. 피부·머리 PNG 마스크별로 해당 Lab 이동량을 적용하되, 원래 픽셀의 L≤18 또는 alpha≤127은 보호하고 알파는 그대로 둔다. 이 규칙과 RGB 범위 잘림을 포함해 기존 Python 베이크와 동일한 결과를 검증해야 한다. 코드의 자료형이 달라도 사람 선택 해시는 u32 하위 비트 연산을 그대로 재현해야 한다.

- 재료 JSON 세 파일과 JSON Schema, 순수 해석 규칙, 시뮬레이션 재료 u32 매핑, 카테고리 폴백 및 외부 로더가 추가로 검증해야 할 관계·경로 제약.
- E–W/N–S 월드 위상, 전체 이웃 점유, 접합부 선택, 남쪽 정면·끝 조각 규칙. 선택된 소스와 그 실패 상태를 함께 넘긴다.
- `FACE_VARIANTS.json`, `variant_transforms.json`, 피부·머리카락 마스크와 실제 베이크 프레임. 게임 셰이더는 룩/변형당 동일한 Lab 이동량을 모든 프레임에 적용하고 알파·윤곽을 보존해야 한다.
- 사람 선택: `h = (agent_id * 2654435761) & 0xffffffff`; 기본 풀의 `h % 6`. 성인 age ≥ 50은 `[v4,v5]`의 `h % 2`; 어린이는 어린이 풀. 누락 룩은 먼저 기존 폴백으로 해석한다.
- 구조·커버리지·맹검의 최종 개별 판정과 보드 해시. 코드나 수치 PASS를 오너 채택으로 해석하지 않는다.

## 오너 결정 필요

윗면 a/b/c 선택과 얼굴 변형 채택은 **오너 판단 대기**다. 이 보고서와 보드는 검토 후보이며 승인 또는 게임 설치를 의미하지 않는다.
