### 구현 방법
- **밤별 소모·날별 낙엽 추첨 — 순수 해시, 저녁 기준 배정**
  - 밤: `u = mix(mix(world_seed ^ 0x4E49_4748_5442_5552) ^ evening_day) % 1000` (솔트는 ASCII "NIGHTBUR")
    - `u < w0`이면 −step, `u < w0+w1`이면 0, 나머지는 +step.
    - `evening_day`는 밤이 시작된 저녁의 표시 날짜다(Pass 7 `night_tick_at` 배정).
    - 따라서 봄 첫날 00:00–07:00의 마지막 겨울밤은 27일 저녁의 추첨을 따른다.
  - 낮: `u = mix(mix(world_seed ^ 0x4641_4C4C_5350_5244) ^ day)`, `delta = u % (2·spread+1) − spread` (솔트 "FALLSPRD")
  - 두 추첨 모두 상태도 난수 흐름도 쓰지 않는다. 혹독함 가중치가 있는 겨울에서만 0이 아니다.
  - 시간당 소모 = `max(1, 혹독함 소모 + 밤 delta)` + 한파 1. 하한 1은 밤 가중치가 있을 때만 적용한다.
  - 하루 낙엽 = `max(0, 혹독함 낙엽 + 날 delta)`. 바뀌지 않은 누산기에 들어간다.
  - 불·probe 키·기록기 열은 모두 한 함수(`night_rate`, `winter_fall_at`)를 읽는다. 그래서 셋이 어긋날 수 없다.
  - Python 독립 구현에서 계산한 리터럴 16행 표로 고정했다(`harness_night_and_fall_draw_table`).
- **마을 사람이 모르는 날씨**
  - `wood_target`, `tonight_burn`, 급한 아침은 계속 혹독함의 소모율(`winter_burn_per_hour`)만 읽는다.
  - 두 겨울의 매 시간에서 추첨이 있는 v14와 없는 v14의 목표·오늘 밤 소모·급함이 같음을 확인했다.
  - 불 자체는 추첨을 본다(`harness_villagers_do_not_see_tonights_draw`).
- **눈 위의 바람**
  - `windfall_over_snow`이면 겨울 windfall이 자리를 최대치까지 채운다.
  - 눈 매장(`bury_wood`)은 각 겨울의 첫 재생 펄스에서만 일어난다. 직전 펄스(현재 틱 − 120)가 겨울이 아닐 때다. 새 상태는 없다.
  - windfall이 없으면 겨울 동안 상한 위로 오르는 자리가 없어서 이 규칙은 아무것도 바꾸지 않는다.
  - 이를 증명했다: v13 + 플래그 vs v13, 시드 0–3 × 35일, 60틱마다 `state_digest`가 같다.

### 기능 설명
- **플레이어 관점**
  - 같은 보통 겨울이어도 밤마다 장작이 줄어드는 속도가 다르다. 불이 한 번도 꺼지지 않는 겨울도 있고, 서너 밤 꺼지는 겨울도 있다(보통 겨울의 꺼진 밤 0/1/2/3/4: 튜닝 17/20/9/3/1, 검증 48/31/19/10/0).
  - 숲에 떨어지는 가지 수도 날마다 ±2 달라진다.
  - 마을 사람은 오늘 밤이 유난히 추울지 모른다. 장작 목표와 서두르는 아침은 그대로 혹독함 기준이다.
  - 겨울에 바람(windfall)을 쓰면 가지가 눈 위에 실제로 쌓인다. Z6 v14에서 8/8 시드에 10 단위가 적용됐다(Pass 7은 2/8).
  - 굶주림·탈수 사망은 모든 시드에서 0이다. 봄·여름·가을은 Pass 7과 같다.
  - 라이브 게임은 `game_v14`로 시작한다.
- **세계 모델 연구 관점**
  - 혹독함이 보이는 라벨에서 숨은 날씨로 바뀌었다. 혹독함만으로 설명되는 꺼진 밤 분산(R²)이 줄었다: 튜닝 0.943 → 0.530, 검증 0.943 → 0.602.
  - 데이터셋 v1: 432 에피소드. 관측 필드 목록이 메타에 있다.
  - 벤치 v1: 숨은 날씨를 추론해야 하는 과제(T3b)가 생겼다. 관측 리지 MAE 0.600은 훈련 평균 0.995보다 훨씬 낫고, 혹독함 오라클 0.609와 비슷하다.

- **겨울이 라벨이 아니라 읽어 내야 하는 날씨인가?** 대체로 그렇다.
