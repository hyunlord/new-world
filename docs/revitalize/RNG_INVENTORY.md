# Randomness and order-dependence inventory (Pass 9 Part 0)

Base: `4c35e295` (line numbers are at that commit). Scope: `rust/crates/sim-core/src`, `sim-systems/src`, `sim-engine/src`, `sim-bridge/src`. Search: `next_u64`, `next_step`, `MovementRng`, `MovementRng::new`, `splitmix`, `mix(`, `h64`, `_SALT`, `world_seed`, `wrapping_mul(0x` (133 hits, every non-test hit is below), plus a read of every system registered in `sim-systems/src/lib.rs` for loops whose outcome depends on hecs query order or hash-container order (a separate read-only survey; results in table 2).

There is one generator in the codebase: `MovementRng` (`sim-systems/src/runtime/agent/movement.rs:63`), a splitmix64 state. Every pseudo-random value is either a draw from a `MovementRng` stream or one splitmix64 output (`MovementRng::new(x).next_u64()`, named `splitmix64` in `worldgen/noise.rs:4` and `mix` in `firewood.rs:52`) of a key. No `rand`, `thread_rng`, `SystemTime`/`Instant`, thread id, rayon reduction or `DefaultHasher` feeds the simulation.

"State-dependent count" = whether the number of draws taken from the stream depends on simulation state (which is what makes a later draw shift between the arms of a fork). v15 keys use the primitive of section 6.2 (`sim_core::rng::keyed_u64(seed, stream, subject, tick, slot, replicate)`); `r` = `SimResources::noise_replicate_for(tick)`; `key` = the resident's `Lineage::key`.

## 2. Order dependence (hecs query order and hash-container order)

hecs order changes with history (swap-remove on despawn, archetype moves when `SeekTarget`, `Child`, `Elder`, `Cold`, `SettlementMigrant` are inserted or removed). `std::collections::HashMap`/`HashSet` use a random `RandomState` per map, so their order differs between processes and between the two arms of a fork even for the same keys.
