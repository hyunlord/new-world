# ADR 0056: Publish presentation with baseline stewardship

## Context

M-LOOP ended unpublished after failing its held-out stewardship bars. Its presentation evidence was promising but belongs to older revisions. The owner authorized M6b Stage −1 to separate that presentation from experimental default behavior, preserving the evidence branch and retained mechanisms.

## Decision

Restore the published BASE eight-rule policy through data and inert defaults, retain optional mechanism code and the appended command, and require all named fixture comparisons against fbc03bdd to match. No fixture is declared changed. Expiry and founder-role presentation issue no orders; explicit player choices use existing command validation.

Use one strict pairwise summary normalizer with qualified exclusions documented in `docs/v8/m6b/MINUS1_NORMALISATION.md`. Historical candidate-only observer vectors may be excluded only under the pinned BASE schema adapter; shared observer values remain significant.

Separate save format15 from the historical format14 steward layout. Freeze the formats11–14 steward payload instead of constructing historical fixtures from the current type. Reject unpublished or ambiguous M-LOOP format14 payloads explicitly; never rewrite original evidence. Test genuine published saves and their independently generated continuation.

Stage −1 publication becomes BASE0. Experimental production caps, tools-only survival and teaching cards proceed in Stage1, using the failed LOOP evidence for design and reserved seeds for acceptance.

## Alternatives considered

- Publish failed steward defaults: rejected by the owner's held-out decision.
- Delete new mechanisms: rejected because the owner requires keeping the code and explicit command.
- Broad recursive normalization or changed-fixture exemptions: rejected because they can hide behavior leakage.
- Keep format14 with serde defaults: actual BASE save decoding failed; positional bincode fields require a versioned layout.
- Guess between unpublished and published format14 layouts: rejected for ambiguous bytes; preserve source evidence and return an explicit error.

## Consequences

The stage includes genuine compatibility and presentation-action repairs but no intended change to BASE simulation behavior. Raw failure evidence, historical LOOP results and spent seeds remain preserved. Full identity, cards, visual review and exact-commit full gate must all pass before publication. A unit test or historical screenshot score is not publication evidence.
