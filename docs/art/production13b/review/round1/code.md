## Findings

### Important — P2: retain the inherited W500 pair-consistency requirement

- Location: `tools/art_pipeline/validate_walker_pairs_p13b.py:171` (also rule description at lines 188–189).
- The walker verdict applies `faster >= 2` only to W200: `(world != "W200" or faster >= 2)`. Thus W500 can pass with only one faster pair, provided the pooled ratio is <=1.00.
- GOAL 4.4 explicitly carries over Art Pass 13 5.1 acceptance and replaces the W500 pooled threshold with <=1.00. It does not explicitly waive 5.1's independent requirement of at least two faster pairs on each workload. Keep that remaining condition rather than silently broadening acceptance.
- Fix: apply `and faster >= 2` to both worlds while retaining the separately reported W500 pooled ceiling. Update the rule text accordingly. A documented contrary interpretation would need to identify the authority for dropping the pair condition.
- **Current result unaffected:** `walker/performance/comparison-attempt2/walker-pairs.json` has W200 ratios `[0.6472445182, 0.6466932538, 0.6541020268]`, W500 `[0.9499485291, 0.9436013447, 0.9386296695]`; both are 3/3 faster and satisfy even the inherited <=0.97 rule.

### Minor — P3: duplicate-ID sorting equivalence is asserted more broadly than tested

- Locations: `rust/crates/sim-bridge/src/ffi/art_kernels.rs:617` (custom Godot-order claim), `:727` (sort), `:1041` (duplicate spatial test), `scripts/test/art/walker_fixture_recorder_p13b.gd:68` (duplicate real rows rejected).
- The actual-call fixture establishes unique real IDs. The duplicate-ID unit test verifies spatial relocation/exclusion, not the custom introsort's equal-comparator order. The numeric fixture tests transforms, vector math and rounding, not sorting. Therefore the evidence does not independently establish duplicate sort order, despite the comment claiming reproduction specifically for duplicates.
- This does not invalidate the observed unique-ID workloads. Keep the limitation explicit; if arbitrary duplicate-ID parity is claimed, add a Godot-produced ordinal-order fixture with >16 rows, equal IDs interleaved with distinct IDs, and multiple tie layouts after the freeze. No need to rerun expensive real captures merely for this coverage improvement.

### Minor — P3: malformed identity evidence can terminate before writing its failure verdict

- Location: `tools/art_pipeline/validate_walker_identity_p13b.py:198–204`.
- `compare(...)` is outside the exception handling and assumes some nested values have their expected types; malformed series can raise `TypeError`/`AttributeError`. The pixel comparator raises `typer.BadParameter` for a wrong schedule or dimensions, which is not caught by the listed exception tuple. In those cases the output directory is created but `walker-identity.json` is never written, despite the preceding run validation collecting errors.
- This fails closed, so it cannot incorrectly accept a candidate. It is a failure-report completeness issue. Convert anticipated malformed-input/comparator exceptions into recorded errors and emit a terminal FAIL report. No observed complete capture is asserted to hit this path.
