## Time projections that are justified, and those that are not

- Body frame: exact selected frame index plus frame-group/config identity is sufficient for `choose`; FPS is 8 walk/carry/run, 1.5 idle, otherwise 4 (`agent_activity80`). Daily Play needs its additional `floor(seconds*2) mod 2` phase.
- Facing: idle time is used only through >=1s by render_facing; still accumulate full idle time. Pickup/meal outputs are booleans only after their stateful updates have run. Stationary seconds remains a full live draw-row value for seats.
- Cold shiver phase can describe its scalar offset, but the offset must still be applied after global geometry. Cold breath has continuous alpha and rise (`cold_effects16`), including rise on invisible existing children; full seconds or exact derived float outputs required.
- Morning chill appearance needs exact alpha, since_tick and breath output, not merely crossed/not-crossed. Continuous time means most cold/chill frames cannot skip these writes safely under a whole-body-and-post-loop memo.
- Oracle metadata exposes raw animation seconds. Camera transform influences global walker geometry even if sprite choice stays identical. No tick-only, offscreen-only or viewport-only shortcut meets this contract.

## Feasible boundary and recommendation

A conservative candidate can update all stateful timers first, derive the complete activity/pose/frame decision, compare an owned immutable exact key, and skip only repeated frame/variant/metadata/CarryLoad/icon writes (roughly renderer226–266). Keep selection observation and row creation unconditional; keep the entire post-loop effects/geometry unconditional. Its key contains actual resolved choice (including icon/fallback), look/life stage, entity/tile/activity/pose/base_pose/facing/moving, founder/carried values, pickup/meal, arrival/daily kind, visibility/capture and zoom, relevant sprite source configuration and all output metadata values. Since derivation still runs, this does **not** establish the intended whole-body recomputation saving; measure before widening or claiming candidate(b) success.

Skipping resolver work itself needs a pre-resolution key containing all inputs above, including timer projections proven valid for each consumer, talk/daily context and animation selection dependencies. That may cost more than it saves. Exact arrays/owned projections are required; hashes alone and mutable dictionary aliases do not prove equality. New sprites, selected agent, reset, locale change, capture/oracle toggle always miss. Reset/retirement clear entries; flags/config changes invalidate. Part3 porter data adds per-entity stage/kind/current carried values and destination/home context; its snapshots and W-multi running identity must be integrated before accepting this candidate.

Recommendation: **drop (b) if the remaining Part1 budget cannot cover complete key implementation plus W-multi identity and three valid alternating pairs for each required workload.** An inventory or property-write-only prototype is not accepted frame-budget work.
