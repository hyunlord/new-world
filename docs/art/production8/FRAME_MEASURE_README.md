# A30 frozen-world CPU measurement

`capture_framings.gd` with `--plan art_society` and `CAPTURE_SOCIETY_PERF_ONLY=1` writes `frame_times_soc_layers.json` in the capture output directory. The parent capture launcher supplies the seed/run identity and `WORLDSIM_GIT_SHA` as usual. This is a windowed runtime measurement; the helper unit test does not establish performance acceptance.

The capture replays seed 20261013 to tick 126994 (first confirmed three living settlements), selects the original settlement so the outline branch is exercised, and freezes the simulation and FV camera. Twelve alternating on/off blocks each contain 50 counted frames, giving 300 per condition. Three rendered frames are discarded after each toggle to isolate delayed GLES timer readback. Raw process and viewport timestamps may refer to adjacent frames, but remain within the same frozen condition after this discard period.

`frame_cpu_probe.gd` measures elapsed monotonic microseconds between real Node `_process` callbacks at priorities -1000 and +1000. It rejects mismatched process-frame stamps. The end callback defers a captured-sample signal until process callbacks drain. The collector awaits that signal and calls `RenderingServer.force_draw(false)` synchronously, so obscured macOS windows cannot stall a wait for automatic drawing. Forced drawing is outside the measured process bracket and uses identical conditions in both branches. After that draw, `frame_measure_session.gd` records the viewport render CPU, frame setup CPU, GPU timer, and wall-clock pacing independently. The A30 primary sample is `process_ms + render_cpu_ms`; `setup_cpu_ms` is separate and `total_with_setup_ms` is diagnostic. GPU zero is reported as unavailable. Entirely zero viewport CPU invalidates measurement. The legacy `_measure_frame_times` remains explicitly labelled a pacing diagnostic. Part 5 changes its pacing loop from `frame_post_draw` waits to `process_frame` plus `force_draw(false)` to avoid macOS obscured-window hangs; its output records `pacing_changed=true`, `forced_draw=true`, and the historical metric name. These new pacing samples are not directly comparable to the historical automatic-draw samples and never substitute for A30 CPU measurements.

Vsync is disabled for collection. Prior vsync, layer state, camera process mode, and selection are restored, and temporary probe nodes removed before evidence writing, including handled validation failures. The exclusive capture viewport starts with render-time measurement disabled and is returned to that state; Godot has no measurement-enable getter. A process termination cannot execute cleanup. Invalid sample/state/restoration evidence produces `valid=false`, not a performance pass.

Acceptance uses the median of each condition's primary samples: on ≤ 1.15 × off **or** on ≤ off + 1.0 ms. Setup and pacing remain available in every raw runtime sample. Tick, camera, zoom, population, living-settlement count, and selected ID must remain unchanged. Load/process snapshots before and after include cargo, Rust, probe, and Godot processes.
