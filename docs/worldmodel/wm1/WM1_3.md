## 8. Dataset v2: how many worlds, which worlds

**(a) Was WM-1.2's tie a data limit, a steps limit or a real tie?** Mostly a steps limit for the model, and a data
limit for the calendar family. On the new 80-world test, the same N = 80 runs score 0.214 at their WM-1.2-rule
checkpoints and 0.197 at their long-run best (Δ_steps −0.017 [−0.020, −0.014]); five times the worlds adds −0.002
[−0.005, 0.000] for the model and −0.020 [−0.024, −0.016] for `an5`. At N = 400 the model beats `an5` on the raw
score with an interval below 0 (Y1 WEAK, −0.013 [−0.019, −0.008]; Y1b WEAK at 24 h, −0.025 [−0.027, −0.023]), but
at N = 400 the bias-removed score is a tie (Y2: +0.002 [−0.003, 0.008]): there the model's edge is a better reading of
each world's level, not a better forecast of how the world moves within a week. (At smaller N the bias-removed
comparison is −0.004 [−0.009, 0.002] at N = 80 and −0.006 [−0.012, −0.001] for the single N = 200 seed, against a
weaker `an5`; not pre-registered.) So at N = 400 it is not a "real tie" on the raw score, and it is a real tie on the
bias-removed score.

**(b) Worlds and budget for WM-2.** For the model, N = 80 training worlds already give 0.197, N = 200 0.187 (one seed) and N = 400 0.194:
more `game_v16` worlds are not what limits it. For the comparison, the calendar family needs a large library (it is
still improving at N = 400: 0.215 → 0.207), and the *test* needs many worlds: on 80 test worlds the 168 h interval of
model − `an5` is about ±0.005 wide each side; on WM-1.2's 16 test worlds it is about ±0.010 (and there the same models
are level with `an5`, 0.198 vs 0.198 — a different set of worlds, not just a wider interval). Recommended: **≥ 400
train, 80 val, ≥ 80 test worlds per scene** (the val/test sizes set the interval width; the train size is set by the
calendar baseline, not by the model), and a training budget of **≥ 9,000 steps at k = 168 (≈ 4 h per run on the
GB10, one run at a time) with a patience window of ≥ 1,800 steps**, three seeds per configuration (≈ 12 h per
configuration). Runs still improved at 9,000 steps; a WM-2 budget of 12,000–15,000 steps per run should be measured
on one seed before fixing it.

**(c) Do `game_v17`'s splits make forecasting harder for the calendar family than for the model?** No — the opposite. On `game_v17` the calendar family holds up and the model loses ground: the raw lead at 168 h
falls from −0.013 [−0.019, −0.008] (`game_v16`) to −0.002 [−0.008, 0.003] (TIE), at 24 h from −0.025 to −0.009,
and the bias-removed score goes from a tie (+0.002) to a loss (+0.013 [0.007, 0.018]). The analog forecaster borrows
whole trajectories of the most similar training worlds, splits included, so a world that splits is forecast by
worlds that split; the model forecasts settlement sums whose make-up changes when a daughter forms, and nothing in
its state at day 8 anticipates the split better than the raw row does (Y6). (nMAE is normalized by each scene's own
split std, so only the model − calendar differences within a scene are compared here, not the levels.) Two seeds only, and
neither `game_v17` run was tuned for this scene (same recipe, same 9,000-step cap).

**(d) What `game_v18` must deliver.** For dataset v2 to be worth recording, `game_v18` (Pass 12, frozen `8142cc3a`; hazard-driven fission) must give
between-world differences that are *history*, not level. This run shows why: on `game_v16` the model's whole raw
edge is the world's level (Y2 TIE), and on `game_v17` the splits are largely a threshold of the early population
(Y6: the raw day-8 row predicts "splits by day 120" at 0.93), which the analog library copes with better than the
model (Y4br NONE). Pass 12's **UBS** (unexplained between-world share: the part of the between-world variance of a
variable at days 60/90/118 that a ridge on each world's static and early-level features does not explain) is the
right gate, with its stated caveat that a nonlinear static effect (such as a population threshold) also counts as
"unexplained" (Pass 13, in progress on the same branch, adds a path-share measure for exactly that reason; its
`game_v17` value for `alive` is near 0, which agrees with the threshold reading). Concretely, before a v2 recording: (1) UBS of food, alive and wood on `game_v18` above `game_v17`'s
with a paired interval excluding 0 — Pass 12's J7b found the food and alive intervals including 0 and J7 failed on
wood (η² 0.236, R²_abs 0.749), so v18 does not yet meet this; (2) first-split timing that varies and is not a function
of the hidden parameters (v18: median day 38, IQR 38, |r| ≤ 0.16 with every hidden parameter — this part is met);
(3) the recorder equivalence of 6.1 against the WM-1.3 recordings on shared columns, and the input list fixed per
dataset as here; (4) the sizes of (b): ≥ 400 train, 80 val, ≥ 80 test worlds per scene, with `game_v16` kept as the
no-split control. A `game_v18` world family that passes (1) is where a learned model has something to learn that a
library of analog worlds cannot copy.

## 9. Limitations

- **Convergence.** Every `game_v16` run ended on the 9,000-step cap; 5 of the 8 runs are "not converged"
  (best step in the last 10 %). Δ_data was measured with step-capped training; whether more steps would help the
  N = 400 runs more than the N = 80 runs was not measured.
- **Seeds.** N = 200 has one seed, N = 80 and `game_v17` two; the bootstrap resamples worlds, not seeds. The N = 80
  seeds differ by 0.012 at 168 h, about as much as the N = 400 model's lead over `an5`.
- **"Not converged" flags** are shown in the Y, Y5 and convergence tables (METRICS amendment item 3); the per-seed
  rows of Appendix A, the skill numbers and Y3 use the same runs (5 of the 6 `game_v16` runs not converged).
- **Bias-removed baseline.** `cal_best_anom` is the val selection on the bias-removed task (`an5` at 168 h); a model
  and a baseline that are both re-centred per world compare only the movement within a week.
- **`game_v17`.** One recipe, untuned for splitting worlds; the model forecasts settlement sums; the first-split day
  varies by only 1–7 days (one test world at day 85), so its probe R² says little.
- **Data description before the pre-registration** (METRICS amendment 2): `w13_describe` read the test split's η²
  and fission labels at 12:10–12:12; it scores no forecaster and selects nothing.
- **Operations.** One training hung in a CUDA call after NVRM out-of-memory errors on the shared DGX and was restarted
  (≈ 47 min; DECISIONS G4.3); four session pauses and one 65-minute loss of the Mac–DGX path (jobs unaffected).
  GPU reproducibility is not measured.
- nMAE is divided by each split's own std, so scores of `game_v16` and `game_v17` are compared through model −
  baseline differences, not across scenes.
