## Part 1
- **L1.1 Families recorded world by world.** `--fork-tick` is per recorder call, and every val / test world has its own c_w, so each family is one call (`--seeds s..s+1 --fork-tick c_w --replicates 1 --schedule-dir obs/schedules/fam/s<seed>/ --include-factual`); `obs/schedules/fam/s<seed>/ref.json` (c_w, the cast) sits beside the three schedule files and is not read by the recorder (it reads only `s*.json`).
- **L1.2 Manifest.** `obs_manifest.json` paths are relative to `WM_DATA_ROOT` (`obs/…`), as `wm1.data.load_split` reads them; `schedule_id` is `obs` for a casting world's observed episode and `none` otherwise; the family members carry `obsfam_<id>` with `none` included (`obsfam_none`). The test worlds' observed episodes are not in any split (no group reads them).
- **L1.3 Checks beyond GOAL.md 6.2.** `fam-check` also asserts that a family's `none_r0` equals the world's factual episode and that a casting world's observed `_obs` episode equals its family member of the same arm, both by per-array sha256 (the fork with replicate 0 is a no-op), and that every family member's single record has the arm's kind, amount and tick c_w.

## Part 2
- **L2.1 Control units on decision rows only.** GOAL.md 7.2's control set is C = {(k, c): k cast at no decision row j < c + h}; a unit (k, c) also needs c to be a decision row of k (alive, a settlement), because the treated are drawn only there (positivity; with p = 0 at c a dead world would enter the control mean with no treated counterpart). No world of the obs split has a non-decision row in days 8 … 60 (policy summary `non_decision_rows` 0), so this changes nothing on this data.
- **L2.2 Baselines' split shift.** `naive`, `ipw` and `match5` predict the restricted split-day shift by the same construction on the restricted split day from c (controls of h = 720). The shift is reported, never judged (12 cells per lag).
- **L2.3 CRN / CT epochs.** The authors' epoch counts are for 10,000 training sequences; WM-4's 400 (obs) would give 450 CT optimizer steps. Epochs are scaled to the authors' number of optimizer steps (METHODS.md D7), each run capped by its time budget.
- **L2.4 CRN / CT checkpoint selection and the grid.** The best validation-factual-loss epoch is kept (METHODS.md D8); the grid's chosen member is the method's `_obs_s0` run itself (no retraining), so the grid's time is the s0 run's time (4 × 20 min ≤ GOAL.md's 1.5 h).

## Part 4
- **L4.1 One queue.** `wm4/_setup/queue.sh` runs every training (and every cost check) one at a time from `queue.txt` lines `RUN SHA BUDGET CMD`, re-read before each run; when no line is pending it waits, so lines are appended as their code and data exist. Test evaluations are never launched by the queue (they wait for METRICS.md part b, `finals4.sh`).
- **L4.2 Hazard recalibration ran beside the first ablation run.** The three Platt fits (9.4) are 745 frozen-trunk 720-step rollouts each plus two val calibrations (≈ 80 s per seed), an evaluation-sized GPU job, run at 23:28–23:32 beside `wm3_ctrl_s1` rather than queued behind four trainings (train and val data only).
