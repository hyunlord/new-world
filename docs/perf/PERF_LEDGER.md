# Performance ledger (ADR 0016 C3)

One block of rows per pass, appended by `tools/v8/bench_ledger.py append` from a run of the standing benchmark
(`worldsim_perf bench`, `sim_test::bench`; method in M1.5 DECISIONS D10): the colony world 192 × 192 (seed
15100, `WorldGenConfig::colony_stress`, fed as `worldsim_perf quick` is) at N = 200 / 1,000 / 2,000 without orders,
N = 200 with the scaled U-script (`tools/v8/bench_script.json`), and N = 200 on 64 × 64 (for the per-tile memory
figure); 1,440 warm-up ticks, then 2,880 profiled ticks; release build; medians of 3 repeats. Times are µs per
tick (`tick_profiled`). RSS/agent is the slope of the resident size after `build_world_with` between N = 200 and
2,000; RSS/tile the difference between 192² and 64² at N = 200. Since M5 (goal §4) alloc/agent is the same slope
read from the allocator byte counter (`sim_core::alloc::Counting`, the global allocator of `worldsim_perf` only):
live heap bytes after the build, exact and independent of page granularity; rows before M5 leave it empty. The load
column holds the host's 1/5/15-minute load averages before each repeat (the Mac is shared: a contended session is
said so in the note).

The gate step `bench` (`tools/v8/bench.sh`) compares a fresh run with the latest quiet pass's rows: more than +10 % on
a scene's tick mean or p99, or on the memory per agent, fails unless the pass's CHANGELOG justifies it
(`--justified`). Since M4 (goal 3.6, the ledger rule) a run with any repeat started at a 1-minute load of 8 or more
is contended: `bench_ledger.py append` takes it only with `--note` and marks its notes "contended, not a base: …",
and `check` never compares against such rows (the M3 session of 2026-10-22 21:14, load 18.6–24.7, is re-labelled
so; its quiet re-measure is the M3 pass row).
Since M5 (goal §5.3, the ledger rule, second fix — M4 appended its rows before its gate, so the gate compared M4 with
M4): `check --pass NAME` skips the rows labelled with the candidate's own pass (and, with `--base COMMIT`, rows whose
commit descends from the base), so the candidate meets the previous pass; the memory rule is on alloc/agent when
both the base rows and the run have it, and RSS/agent is then information only (against a base without alloc/agent
the RSS rule still decides); `append` needs `--gate-log <log_dir>/gate.txt` of a green gate on the run's commit, so
a pass appends its rows only in its report step, after the gate. A quiet re-measure of an older pass that already
passed its gate is appended with `--re-measure "re-measure: …"`, which becomes the rows' note.
C3's ceilings (N = 1,000 mean ≤ 5 ms, N = 2,000 ≤ 10 ms, ≤ 4 KiB per agent, ≤ 96 B per tile) are reported PASS/MISS
and do not fail the gate in M1.5.
