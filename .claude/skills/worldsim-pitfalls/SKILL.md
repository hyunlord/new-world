# WorldSim pitfalls — the problem log

One row per real problem that cost us a retry, a wrong claim or a lost run, and that can still happen in V8.
The Rust, Godot and testing skills hold the rules for their area (`worldsim-architecture`, `worldsim-godot`,
`worldsim-testing`); this log keeps the cross-cutting and process lessons, and repeats the few domain lessons that
every agent must know even when it is not working in that area. Sources are commit hashes or paths at tag
`v7-final-art` (`git show v7-final-art:<path>`), or current paths.

## Rules

- **Do** grep the code before believing a note that a feature is "missing", and check its wiring (registered in `register_default_runtime_systems`, which `build_game_engine` reaches through `build_world_with`, and listed in the generated system table of `docs/ARCHITECTURE.md`; reachable from the bridge). *Reason:* 10 of 11 features labelled missing in April 2026 were 85–100 % implemented; one system existed but was never registered.
- **Do** run identity (`tools/v8/identity.sh`) before writing "no behaviour change". *Reason:* only summaries plus chronicles compared by content prove it; reasoning about a diff does not.
- **Do** write a claim (test passed, identity green, review fixed) only after its artefact exists; mark it PENDING until then. *Reason:* V7 reports cited checks that had not run, in four passes.
- **Do** run the final gate on the exact commit you report, with nothing edited or committed while it runs. *Reason:* a green gate once covered three different trees.
- **Don't** change a gate's instrument (a ceiling, a metric's source, a tool) while a gate runs: stop the gate, record the finding in DECISIONS, change the instrument in its own commit, and start the gate again from step 1. *Reason:* M5 moved the memory ceilings to the allocator counter by stopping a running gate (D19); the change was sound but the contract (ADR 0016) did not say it until M5.5 amended it.
- **Do** stage explicit paths (`git add path …`); never `git add -A`, `git add .` or a whole directory. *Reason:* one directory add took 165 untracked gate logs into history; graft and OMC leave local files in the tree.
- **Do** verify every push with `git ls-remote origin <branch>` against local `HEAD`. *Reason:* two pushes were silently missing on the remote.
- **Do** run one Claude Code session per checkout: stop and report when another session's files or process are in the
  tree. *Reason:* D19 was committed by a second session in M-ART2's checkout mid-gate and stayed ungated (M-ART2.1 D1).
- **Don't** touch `.claude/settings.json` or its skip-worktree flag; never `git add` it; never install the V7 hooks. *Reason:* the harness hooks hijack unattended runs; the local file is `{}` with skip-worktree.
- **Do** keep raw measurement output (probe runs, captures, logs) outside the repository. *Reason:* raw probe data filled the disk, and V7's `docs/` grew to 1.5 GB of evidence.
- **Do** count every executed check toward a "three attempts" limit, debug runs included. *Reason:* one repair ran 10 attempts against a 3-strike limit.
- **Do** ask "which bug would still pass this test?" and see a new test fail before trusting it. *Reason:* tests passed with nothing checked (0 cancels, missing inputs, vacuous fixtures).
- **Do** treat absence as failure: zero selected items, a missing input file or an unknown label fails the check. *Reason:* several V7 checks reported PASS on nothing.
- **Do** give every subagent reviewer a file to write its report to, and run it on brief + diff + outputs only. *Reason:* final messages came back empty or truncated; a fresh reviewer recomputing from raw data found real bugs.
- **Do** label hypotheses as hypotheses and state the registered verdict first. *Reason:* reports overstated results (a passing tuning value cited, the failing evaluation omitted).
- **Do** run long jobs with an owned `caffeinate -i` and kill timed-out work by process group. *Reason:* the Mac slept for 1 h 43 min mid-gate; a killed `cargo` left its test binary running and loading the CPU.
- **Do** write bash for macOS bash 3.2 (`${a[@]+"${a[@]}"}` for possibly empty arrays; no GNU-only flags). *Reason:* `set -u` with an empty array broke scripts twice.
- **Don't** rewrite pushed history or force-push to fix a mistake; fix forward in a new commit. *Reason:* parallel worktrees and pins refer to pushed hashes.

## Procedures

### Add an entry
1. Add an entry when a problem needed more than one attempt, a result was wrong or overstated, a better method was found, or a tool behaved unexpectedly — in the same pass.
2. Decide where it belongs: a rule that only changes Godot work → `worldsim-godot`; Rust/ECS/determinism → `worldsim-architecture`; tests/identity/perf → `worldsim-testing`; anything cross-cutting, process, git, environment, or a domain lesson every agent must know → here.
3. Write one row: `| date | symptom | root cause | fix | source |`.
   - date: the day it happened (commit date, or `git blame` date of the record line);
   - symptom: what was seen, with numbers; start with the tag in bold (`**rust**`, `**testing**`, `**godot**`, `**process**`) and keep the table sorted by tag;
   - root cause: why — the mechanism, not "a bug";
   - fix: what to do next time, imperative;
   - source: a commit hash and/or a path in backticks (at `v7-final-art` if the file is gone). No source, no row.
4. Never use `|` inside a cell (write "or"); `tools/v8/check_docs.sh` splits rows on `|` and requires the last cell to hold a backticked path or a hash.
5. If the lesson changes how everyone works, add a one-line rule above as well. Over 400 lines: move the oldest rows to `references/lessons-archive.md` and link it.
6. Run `bash tools/v8/check_docs.sh`.

### Before a non-trivial change
1. Read this table's rows for the tags you will touch.
2. Grep for the feature's symbols and callers (every caller of every function that can set the value you change).
3. Note the identity, determinism and smoke checks the change needs, and run them before claiming anything.
